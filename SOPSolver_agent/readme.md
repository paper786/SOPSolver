# SOPSolver Agent Solver User Guide

This folder implements a Python-based SOPSolver multi-agent experimental framework:

- `main.py`: Reads prompts, benchmark cases, and BestRecord, and coordinates Agent1, Agent2, and Evaluate_Agent.
- `agent1.py`: Implements Agent1, the shared API client, Excel/text utilities, LLM request-response logging, and the offline template mode without an API key.
- `agent2.py`: Implements Agent2, which is required to follow a design strategy different from Agent1.
- `evaluate_agent.py`: Runs the MATLAB code generated by the two agents, compares performance, generates feedback Markdown files, saves the final algorithm, and writes results to the result table.

## 1. Environment Check

The framework automatically detects the project root directory. If automatic detection fails, set `SOPSOLVER_PROJECT_ROOT` or explicitly pass `--project-root`.

```powershell
python main.py --doctor
```

The check should detect the following items:

- `prompt_SOPSolver.md`
- `Statistics\BestRecord.xlsx`
- `Statistics\Algorithm_information.xlsx`
- `CEC2017\CEC2017_evaluate.m`
- `CEC2019\CEC2019_evaluate.m`
- `openpyxl`
- MATLAB command

If the MATLAB command is not `matlab`, specify it manually:

```powershell
python main.py --doctor --matlab-command "E:\matlab\bin\matlab.exe"
```

## 2. API Configuration

Formal LLM experiments require an OpenAI-compatible API key. It is recommended to use environment variables and not write the key directly into the code:

```powershell
$env:SOPSOLVER_API_KEY="YOUR_API_KEY"
```

Default API settings:

```text
SOPSOLVER_API_BASE_URL=https://api.openai.com/v1
SOPSOLVER_MODEL=gpt-5.5
```

Example settings for another compatible API:

```powershell
$env:SOPSOLVER_API_BASE_URL="https://api.deepseek.com/v1"
$env:SOPSOLVER_MODEL="deepseek-chat"
```

Test the API:

```powershell
python main.py --api-smoke-test
```

## 3. Pipeline Verification Without an API Key

If no API key is available, use offline template mode. This mode does not claim to produce a high-performance algorithm designed by an LLM. It is only used to verify that:

- Candidate MATLAB code can be generated.
- Evaluate_Agent can call MATLAB.
- Feedback Markdown files can be generated.
- `final_code` can be saved.
- `Statistics\result.xlsx` can be written.
- `sopsolver_artifacts` can retain request-response records.

```powershell
python main.py `
  --offline-template `
  --suite CEC2017 `
  --function 1 `
  --dimension 10 `
  --max-iterations 8 `
  --population 8 `
  --time-limit 30 `
  --max-rounds 1 `
  --pilot-runs 1 `
  --final-runs 2 `
  --force-formal-on-last-round
```

## 4. Formal Single-Case Run

Example: CEC2017 F1 100D, with a maximum runtime of 5 minutes for each single algorithm run and 10 independent final runs:

```powershell
python main.py `
  --suite CEC2017 `
  --function 1 `
  --dimension 100 `
  --max-iterations 5000 `
  --population 100 `
  --time-limit 300 `
  --max-rounds 20 `
  --pilot-runs 1 `
  --final-runs 10
```

If a gap threshold is used:

```powershell
--accept-gap 50 --strict-gap
```

## 5. Batch Cases

Example CSV header:

```csv
suite,function,dimension,max_iterations,population,time_limit,accept_gap,strict_gap
CEC2017,1,100,5000,100,300,0,false
CEC2017,30,100,10000,100,300,50,true
```

Run:

```powershell
python main.py --cases-file cases.csv --max-rounds 20
```

## 6. Inputs and Outputs

Read from:

- `prompt_SOPSolver.md`
- `CEC2014_2017_2019_calling_rules.md`
- `Literature`
- `Statistics\BestRecord.xlsx`
- `Statistics\Algorithm_information.xlsx`

Write to:

- `compare_code\*_Agent1.m`
- `compare_code\*_Agent2.m`
- `prompt_agent_evaluate_md\*_prompt.md`
- `final_code\*.m`
- `Statistics\single_result.xlsx`
- `Statistics\result.xlsx`
- `sopsolver_artifacts\<case>\round_XXX\<Agent>\llm_request_response.json`
- `sopsolver_artifacts\<case>\round_XXX\<Agent>\llm_request_response.md`

## 7. Important Notes

This framework only automates the real experimental workflow and does not fabricate results. Results are written to `result.xlsx` or `single_result.xlsx` only after MATLAB successfully runs and returns finite numerical values.


## 8. Notes

The following items need to be configured by the user:
- In `main.py`, line 265, the user needs to specify the local path of the required folder.
- Except for the local paths that need to be specified by the user, all other required files are provided in the supporting materials.
- All input parameters can be customized by the user. Alternatively, the default values can be used, or the parameters can be defined directly in the Python files.
- The saving paths and formats of all output files can be adjusted and defined by the user.
- Due to differences in runtime environments, customized adjustments may be required before the program can run properly.
